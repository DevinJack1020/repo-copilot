# Repo Copilot 设计说明

日期：2026-10-23  
状态：待用户书面复核

## 1. 项目定位

Repo Copilot 是面向公开代码仓库和本地 ZIP 项目的中文 AI Coding 全栈助手。它帮助用户完成代码解释、错误定位、代码审查和测试用例生成，并为每条结论展示文件路径和行号引用。

本项目面向 AI 全栈工程师求职展示，重点证明端到端产品开发、数据库设计、模型接入、安全处理、评估、测试和部署能力。

## 2. 上游与个人贡献边界

- 以上游 [Vercel Chatbot](https://github.com/vercel/chatbot) 的 Next.js、AI SDK、Auth.js 和 PostgreSQL 能力为参考底座。
- 上游使用 Apache-2.0 许可证；使用其代码时保留许可证、版权和 NOTICE 要求。
- 不沿用模板品牌和原始界面。
- 个人核心实现包括仓库导入、ZIP 安全校验、文件过滤、代码索引、引用式检索、四类分析工具、任务状态、评估指标、中文工作台和自动化测试。
- README 必须明确标注“基于开源项目二次开发”，并列出上游能力与个人实现清单。

## 3. 用户与成功标准

主要用户是需要快速理解陌生仓库的学生开发者和初级工程师。

首版成功标准：

1. 用户可以登录并导入公开 GitHub URL 或 ZIP。
2. 系统展示处理进度、文件树、语言分布和索引状态。
3. 用户可以发起代码解释、错误定位、代码审查和测试生成。
4. 回答以流式方式展示，并引用文件路径和行号。
5. 无模型密钥时仍能通过演示模式走完主路径，且明确标注回答来源。
6. 质量看板展示响应耗时、任务成功率、引用覆盖率和用户反馈率。
7. 核心路径通过自动化测试和 CI，可在本地按文档复现。

## 4. 首版范围

### 包含

- 邮箱登录、会话和用户数据隔离。
- 公开 GitHub 仓库 URL 导入。
- ZIP 上传、大小和文件数限制、路径穿越防护。
- 二进制文件、依赖目录、构建产物和常见密钥文件过滤。
- 文件树、语言统计、文本分块、元数据和 PostgreSQL 全文索引。
- 可选的模型向量检索增强；未配置向量模型时退化为全文检索。
- 四种分析任务：解释、排错、审查、测试生成。
- OpenAI 兼容 API 配置、多模型选择和流式响应。
- 本地演示数据与演示回答。
- 文件/行号引用、任务历史、反馈和质量看板。

### 不包含

- 私有 GitHub OAuth 和组织级权限同步。
- 执行用户上传的任意代码。
- IDE 插件、多人协作和自动创建 Pull Request。
- 生产级分布式队列和大规模向量基础设施。

## 5. 架构与组件

- `web`：Next.js App Router，提供中文工作台、认证、Server Actions 和 Route Handlers。
- `repository-ingestion`：校验来源、下载或解包、过滤文件、生成清单并记录处理状态。
- `code-index`：按文件和语言分块，保存路径、行号、哈希和可检索文本。
- `retrieval`：全文检索为必选能力，可选向量检索；合并、去重并限制上下文。
- `analysis-tools`：为四类任务生成结构化提示词和输出约束。
- `model-gateway`：封装 OpenAI 兼容接口、模型列表、超时、流式传输和演示模式。
- `evaluation`：记录耗时、成功/失败、引用数量、引用覆盖和用户反馈。
- `database`：PostgreSQL 保存用户、仓库、文件、分块、分析任务、消息、引用和反馈。

组件之间通过类型化服务接口调用；导入、索引、检索和模型调用分别记录状态，不把所有逻辑堆入页面或单个 Route Handler。

## 6. 数据流

1. 用户提交 GitHub URL 或 ZIP。
2. 系统校验来源和配额，创建 `repository` 与 `ingestion_job`。
3. 导入服务生成安全的文件清单和内容哈希。
4. 索引服务生成带起止行号的代码块并写入全文索引。
5. 用户选择任务并输入问题。
6. 检索服务返回相关代码块；分析工具组装受限上下文。
7. 模型网关流式返回结构化回答；演示模式使用固定样例并显式标识。
8. 系统保存回答、引用、耗时和错误；用户可提交有用/无用反馈。
9. 质量看板聚合任务成功率、P50/P95 响应时间、引用覆盖率和反馈率。

## 7. 界面设计

界面为简体中文，采用深色工程工作台风格。主导航包括“仓库”“分析记录”“质量看板”和“设置”。仓库详情使用文件树、分析对话区和上下文引用区三栏布局；窄屏改为抽屉和标签页。

视觉原则：高信息密度但保留清晰层级；青绿色用于当前状态和关键操作；错误、演示模式和真实模型结果必须有明确、非纯颜色的文字标识。

## 8. 异常、安全与隐私

- 限制 ZIP 大小、解压后总大小、文件数量、单文件大小和目录深度。
- 拒绝绝对路径、`..` 路径和符号链接逃逸；不执行导入代码。
- 默认过滤 `.env`、私钥、凭据文件、二进制、依赖和构建产物。
- GitHub 下载、解包、索引和模型调用分别超时，并提供有界重试。
- 错误返回用户可执行的修复建议，同时在服务端记录关联 ID，不泄露密钥或代码内容。
- 默认不把仓库内容发送到分析平台；只有必要上下文发送给用户配置的模型提供方。

## 9. 测试与验收

- 单元测试：路径规范化、文件过滤、分块、引用映射、指标计算。
- 集成测试：导入任务、数据库状态、检索、模型网关成功/超时/失败路径。
- 安全测试：Zip Slip、压缩炸弹限制、异常编码、密钥文件过滤。
- Playwright：登录、导入样例仓库、发起分析、查看引用、提交反馈、查看看板。
- CI：格式检查、lint、类型检查、单元/集成测试和生产构建。
- 验收基线：新机器按 README 和 `.env.example` 可以启动 PostgreSQL、迁移、种子数据和应用；未提供 API Key 时端到端演示仍通过。
